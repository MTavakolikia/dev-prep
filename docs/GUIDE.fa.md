| ابزار | نسخه پیشنهادی | توضیح |
|---|---|---|
| [Node.js](https://nodejs.org) | ≥ 20 | مدیریت پکیج و اجرا (با npm) |
| SQLite | — | به‌صورت داخلی همراه Prisma هست؛ نصب جداگانه لازم نیست |

## ۲. نصب و راه‌اندازی

### روش ۱ — از روی فایل zip پروژه

```bash
unzip devprep-project.zip -d devprep && cd devprep

# ۱) نصب وابستگی‌ها
npm install

# ۲) ساخت Prisma Client
npm run db:generate

# ۳) اجرا
npm run dev
```

سپس مرورگر را باز کنید: **http://localhost:3000**

> ✅ دیتابیس آماده (`db/custom.db`) داخل zip هست؛ نیازی به seed مجدد نیست. اگر خواستید از صفر شروع کنید، بخش ۴ را ببینید.

### روش ۲ — از روی سورس (بدون دیتابیس آماده)

```bash
npm install
npm run db:generate
npm run db:push      # ساخت اسکیمای SQLite از prisma/schema.prisma
npm run db:seed      # درج داده‌های اولیه (مقالات، سوالات، کاربران و ...)
npm run dev
```

## ۳. پیکربندی (فایل .env)

فایل `.env.example` را به `.env` کپی کنید و مقادیر را تنظیم کنید:

```env
# ---- دیتابیس ----
DATABASE_URL=file:../db/custom.db     # مسیر فایل SQLite (نسبت به پوشه prisma)

# ---- حساب مدیر (فقط از env خوانده می‌شود) ----
ADMIN_EMAIL=admin@devprep.dev
ADMIN_PASSWORD=Forge-Admin-2026!
ADMIN_NAME=Sara Mitchell

# ---- حساب دمو ----
DEMO_EMAIL=alex@devprep.dev
DEMO_PASSWORD=Demo-2026!

# ---- عمومی ----
NEXT_PUBLIC_APP_URL=http://localhost:3000
NEXT_PUBLIC_SITE_URL=http://localhost:3000   # برای sitemap/robots/JSON-LD
AUTH_SECRET=یک-رشته-تصادفی-طولانی
```

**نکته‌های مهم امنیتی:**

- `AUTH_SECRET` را در محیط واقعی حتماً با یک مقدار تصادفی (مثلاً خروجی `openssl rand -hex 32`) عوض کنید.
- رمزهای `ADMIN_*` و `DEMO_*` **فقط** از متغیرهای محیطی خوانده می‌شوند و هرگز در کد هاردکد نشده‌اند.
- در production کوکی نشست به‌صورت `httpOnly + secure + sameSite=lax` تنظیم می‌شود.

## ۴. دیتابیس و داده‌های اولیه

Seed پروژه **دستوری (deterministic)** و **idempotent** است؛ یعنی با اجرای مکرر، داده تکراری نمی‌سازد و خروجی با همان seed همیشه یکسان است.

```bash
npm run db:seed      # درج کامل داده‌ها
npm run db:push      # همگام‌سازی اسکیما (با --accept-data-loss)
```

داده‌هایی که ساخته می‌شوند (ارقام واقعی دیتابیس فعلی):

| موجودیت | تعداد |
|---|---|
| مقالات ۱۱-بخشی | **۱,۹۱۰** |
| سوالات مصاحبه | **۱,۵۴۰** |
| تکنولوژی‌ها (۶ دسته) | **۱۱۰** |
| مسیرهای یادگیری | **۱۷۱** |
| دستاوردها (Achievements) | **۱۰۷** |
| کاربران نمونه، نشان‌ها، نشست‌ها، رویدادهای آنالیتیکس | ✔ |

بررسی سریع تعداد رکوردها:

```bash
npx tsx scripts/check-counts.ts
```

## ۵. اجرا در حالت توسعه

```bash
npm run dev
```

- آدرس: `http://localhost:3000`
- لاگ سرور مستقیماً در کنسول چاپ می‌شود.
- ماژول‌های Server Action در `src/server/actions/` با هر تغییر، hot-reload می‌شوند.

---

## ۶. اجرا در حالت Production

```bash
npm run build        # خروجی standalone در .next/standalone + کپی static/public
npm run start        # اجرای سرور production روی پورت 3000
```

- خروجی به‌صورت **standalone** است و فقط به فایل‌های داخل `.next/standalone` + `public` + دیتابیس نیاز دارد.
- مصرف حافظه سرور production حدود **۱۲۰–۱۶۰MB** است (در مقایسه با ~۳GB در حالت dev).
- هدرهای امنیتی روی همه پاسخ‌ها اعمال می‌شوند: `X-Frame-Options: DENY`، `nosniff`، `HSTS`، `Referrer-Policy`، `Permissions-Policy` و حذف `X-Powered-By`.

## ۷. تست و کیفیت کد

```bash
npm run test            # اجرای یک‌باره همه تست‌ها (۱۵۳ تست / ۱۱ فایل)
npm run test:watch      # حالت watch
npm run test:coverage   # گزارش پوشش کد (v8)
npm run lint            # ESLint — بدون error
npm run typecheck       # tsc --noEmit — بدون error
```

پوشه تست‌ها: `tests/unit/` — پوشش داده‌شده:

- مسیریاب hash (`src/router`) — پارس مسیر، ناوبری، Link، ساخت query
- رمزنگاری احراز هویت (scrypt) و RBAC
- موتور نمره‌دهی مصاحبه (`computeInterviewScore`, `aggregateTopics`)
- قطعیت seed generator (همان seed ← همان خروجی)
- اسکیمای Zod، مپرها، استورهای Zustand، توکن‌های طراحی
- یونیت‌های production: سلامت API، robots/sitemap/manifest، JSON-LD

## ۹. راهنمای استفاده از بخش‌ها

### ۹.۱. صفحه اصلی (`/`)
نمای کلی پلتفرم: دسترسی سریع به مقالات، تکنولوژی‌ها، چالش روز، آمار رشد و پیشنهاد مسیر. برای مهمان‌ها هم کامل قابل مشاهده است.

### ۹.۲. مقالات (`/articles`)
- فهرست **۱,۹۱۰ مقاله** با دسته‌بندی، برچسب، زمان مطالعه و شمارنده بازدید.
- صفحه مقاله (`/articles/[slug]`) شامل فهرست مطالب، هایلایت کد، یادداشت‌گذاری و بوکمارک است.
- کاربران واردشده می‌توانند بوکمارک کنند، یادداشت بگذارند و هایلایت کنند؛ مطالعه برای مهمان آزاد است.

### ۹.۳. تکنولوژی‌ها (`/technologies`)
- **۱۱۰ تکنولوژی** در ۶ دسته (فرانت‌اند، بک‌اند، موبایل، DevOps، دیتا و ...).
- صفحه هر تکنولوژی: نمای **Skill Graph**، مقالات مرتبط، سوالات مصاحبه و مسیرهای یادگیری همان تکنولوژی.

### ۹.۴. شبیه‌ساز مصاحبه (`/interview`)
قلب پلتفرم. حالت‌های مختلف آزمون:

| حالت | تعداد سوال | توضیح |
|---|---|---|
| Quick Practice | ۵ | گرم‌کردن سریع |
| Standard Interview | ۱۵ | شبیه‌سازی مصاحبه واقعی |
| Full Interview | ۳۰ | تجربه کامل |
| Random | ۱۲ | ترکیبی از همه تکنولوژی‌ها |
| Senior Frontend | ۱۸ | سوالات سطح Senior |
| Staff Frontend | ۱۵ | معماری و طراحی سیستم |
| Daily Challenge | ۳ | چالش روزانه برای حفظ streak |

جریان آزمون: انتخاب حالت ← ورود به نشست immersive ← پاسخ به هر سوال («بلدم / سخت بود / رد شدن») ← دیدن پاسخ مدل ← در پایان **نمره، نقاط قوت/ضعف به تفکیک topic و لیست مطالعه پیشنهادی**.

> 🔒 **مهمان‌ها** می‌توانند همه سوالات و پاسخ‌های مدل را ببینند؛ اما برای «شروع آزمون و ثبت پیشرفت» باید وارد شوند — در این حالت پنجره ورود با پیام مربوط به ثبت پیشرفت باز می‌شود.

### ۹.۵. بانک سوالات (`/questions`)
- **۱,۵۴۰ سوال** با فیلتر تکنولوژی/سطح/دسته و جستجوی متنی.
- هر سوال: پاسخ کوتاه + پاسخ تشریحی + سطح (Junior تا Staff) + زمان پیشنهادی.
- بوکمارک سوال مخصوص کاربران واردشده است.

### ۹.۶. مسیرهای یادگیری (`/learning-paths`)
- **۱۷۱ مسیر**: مسیرهای شاخص، مسیر هر تکنولوژی و نقشه راه شغلی.
- ثبت‌نام در مسیر، تیک‌زدن آیتم‌ها و مشاهده درصد پیشرفت که مستقیماً روی Skill Graph اثر می‌گذارد.

### ۹.۷. چیت‌شیت‌ها (`/cheatsheets`)
برگه‌های تقلب فشرده برای مرور سریع سینتکس و مفاهیم.

### ۹.۸. جستجو (`/search`)
جستجوی سراسری در مقالات، سوالات، تکنولوژی‌ها و مسیرها + تاریخچه جستجو. میان‌بر: کلید `/`.

### ۹.۹. داشبورد (`/dashboard`)
مخصوص کاربران واردشده: XP و سطح، استریک روزها، دستاوردهای اخیر، آمار مصاحبه‌ها، نمودار رشد و پیشنهاد هوشمند «قدم بعدی».

### ۹.۱۰. کتابخانه شخصی (`/library`)
همه بوکمارک‌ها، یادداشت‌ها، هایلایت‌ها و تاریخچه مطالعه در یک‌جا.

### ۹.۱۱. دستیار AI (⌘⇧I)
پنل کناری هوشمند که به **صفحه‌ای که در آن هستید** آگاه است — می‌توانید درباره همان مقاله/سوال/تکنولوژی بپرسید. (سمت سرور با `z-ai-web-dev-sdk` پیاده‌سازی شده و کلید API هرگز سمت کلاینت نمی‌رود.)

### ۹.۱۲. پنل مدیریت (`/admin`)
فقط برای نقش‌های AUTHOR به بالا:
- **Overview**: آمار کل پلتفرم و نمودارها
- **Articles**: ویرایشگر کامل با پیش‌نویس/بازبینی/انتشار
- **Questions**: مدیریت بانک سوالات
- **Users**: مدیریت کاربران و تغییر نقش
- **Taxonomy**: دسته‌ها، تکنولوژی‌ها و برچسب‌ها
- **Settings**: تنظیمات پلتفرم

## ۱۰. نقش‌ها و سطوح دسترسی

پنج نقش با سلسله‌مراتب (RBAC):

| نقش | دسترسی |
|---|---|
| `USER` | مطالعه، آزمون، داشبورد شخصی، کتابخانه |
| `AUTHOR` | + ساخت و ویرایش مقالات خود |
| `EDITOR` | + ویرایش/انتشار همه مقالات، مدیریت taxonomy |
| `ADMIN` | + مدیریت کاربران، سوالات، تنظیمات |
| `SUPER_ADMIN` | همه دسترسی‌ها |

منطق سمت سرور: `hasRole` / `requireUser` / `requireRole` در `src/lib/auth.ts` — هر Server Action حساس، مجدداً سمت سرور اعتبارسنجی می‌شود (اعتماد به کلاینت وجود ندارد).

## ۱۲. Health Check و API

```bash
curl http://localhost:3000/api
```

پاسخ سالم:

```json
{
  "status": "ok",
  "db": "up",
  "latencyMs": 10,
  "uptimeSeconds": 42,
  "timestamp": "2026-09-04T05:00:00.000Z"
}
```

اگر دیتابیس در دسترس نباشد، کد وضعیت **503** با `status: "degraded"` برمی‌گردد — مناسب برای load balancer و مانیتورینگ.

فایل‌های SEO و PWA هم به‌صورت route تولید می‌شوند: `/robots.txt`، `/sitemap.xml`، `/manifest.webmanifest` (قابل نصب به‌عنوان اپ موبایل/دسکتاپ).

## ۱۳. عیب‌یابی رایج

| مشکل | راه‌حل |
|---|---|
| `Error: @prisma/client did not initialize yet` | `npm run db:generate` را اجرا کنید |
| خطای اتصال دیتابیس | مقدار `DATABASE_URL` در `.env` را بررسی کنید (نسبت به پوشه `prisma/` است) |
| پورت 3000 اشغال است | `lsof -ti:3000 \| xargs kill` سپس دوباره اجرا کنید |
| داده‌ای نمی‌بینید / صفحه خالی | `npm run db:seed` را اجرا کنید |
| تست‌ها خطای DB می‌دهند | تست‌ها ایزوله‌اند و به DB وصل نمی‌شوند؛ مطمئن شوید `tests/stubs/` دست‌نخورده است |
| خطای Server Action در پشت پروکسی | در `next.config.ts` دامنه خود را به `serverActions.allowedOrigins` اضافه کنید |

## ۱۴. ساختار پروژه

```
├─ src/
│  ├─ app/                 # ورودی Next.js + api/ + robots/sitemap/manifest
│  ├─ features/            # ویوهای دامنه (home, articles, interview, admin, ...)
│  ├─ components/          # shell/ · shared/ · ui/ (shadcn)
│  ├─ server/
│  │  ├─ actions/          # مرز 'use server' (auth, content, interview, ...)
│  │  ├─ scoring.ts        # موتور نمره‌دهی مصاحبه
│  │  └─ engagement.ts     # XP، دستاوردها، استریک
│  ├─ lib/                 # auth/RBAC · db · site · design · slug · utils
│  ├─ stores/              # zustand (UI و وضعیت نشست مصاحبه)
│  ├─ router/              # مسیریاب hash تایپ‌شده
│  └─ db/seed/             # seed composer قطعی + کورپوس موضوعی
├─ tests/                  # ۱۵۳ یونیت‌تست + استاب‌های ایزوله
├─ prisma/schema.prisma    # ۳۱ مدل
├─ docs/                   # مستندات معماری + همین راهنما
├─ scripts/                # ابزارهای کمکی (seed check, icon gen, ...)
└─ db/custom.db            # دیتابیس SQLite آماده
```
